# Error Recovery & Self-Healing Scenario in agy-kit

This scenario details how `agy-kit` detects, analyzes, and automatically recovers from errors (Self-Healing / Error Recovery) when a Unit Test fails during the TDD cycle.

---

## 1. Failure Context

While implementing the **User Registration** feature, the `coder` subagent runs the test suite to transition from **RED** to **GREEN**. However, the password strength verification test case fails:

### Command executed:
```bash
pytest tests/test_auth_register.py -k test_register_weak_password
```

### Returned error log (Stdout / Stacktrace):
```text

    def test_register_weak_password(client, db_session):

            "email": "user@example.com",
```

## 2. Error Recovery Prompt (Sent to Agent)

Sample prompt automatically generated by the agy-kit system to transfer error context to the agent:

```xml
<error_recovery_context>
  <phase>TDD_GREEN_STEP_FAILED</phase>
  <failing_test>tests/test_auth_register.py::test_register_weak_password</failing_test>
  <error_type>AssertionError: Expected HTTP 422 for weak password '123', got 201 Created</error_type>
  
  <stacktrace>
> assert response.status_code == 422
E assert 201 == 422
  </stacktrace>

  <relevant_files>
    <file path="src/auth/schemas.py" lines="10-25" />
    <file path="src/auth/auth_service.py" lines="30-50" />
  </relevant_files>

  <instructions>
    1. DO NOT rewrite or modify the test file `tests/test_auth_register.py`. The test is correct.
    2. Analyze `src/auth/schemas.py` and `src/auth/auth_service.py`.
    3. Identify why a 3-character password ("123") bypassed validation and returned 201 Created.
    4. Apply a targeted patch adding minimum 8 characters and pattern validation using Pydantic Field constraint or regex.
    5. Re-run `pytest tests/test_auth_register.py` to confirm test passes GREEN.
  </instructions>
</error_recovery_context>
```

## 3. Agent Reasoning & Response (`coder`)

### Agent Thinking & Diagnosis:
> "Test `test_register_weak_password` expects HTTP status 422 when password is '123', but the API returns 201 Created.
> Root cause: In `src/auth/schemas.py`, the `password` field in `UserRegistrationRequest` is only declared as `password: str` without applying a `min_length=8` constraint or validator.
> Fix required: Update `src/auth/schemas.py` to add `Field(..., min_length=8, description="Password must be at least 8 characters")`."

### Tool Call 1: Inspections via `read_file`
Agent reads file `src/auth/schemas.py`:
```python
class UserRegistrationRequest(BaseModel):
    email: EmailStr
    password: str
    full_name: str
```

### Tool Call 2: Patch execution via `patch`
Agent performs direct fix:
```patch
*** Begin Patch
*** Update File: src/auth/schemas.py
@@ -10,3 +10,3 @@
 class UserRegistrationRequest(BaseModel):
     email: EmailStr
-    password: str
+    password: str = Field(..., min_length=8, max_length=128, description="Password must be at least 8 characters")
     full_name: str
*** End Patch
```

### Tool Call 3: Verification via `terminal`
Agent re-runs the test to verify:
```bash
pytest tests/test_auth_register.py
```

### Response Result (Stdout):
```text
tests/test_auth_register.py ........                                    [100%]

============================== 8 passed in 0.42s ===============================
```

## 4. Loop Prevention & Stalled Agent Rule

To prevent the agent from attempting ineffective repetitive fixes (Infinite Retry Loop):

```text
               +---------------------------+
               |  Test Fail Detected (1st) |
               +-------------+-------------+
                             |
                             v
               +---------------------------+
               | Apply Error Recovery Patch|
               +-------------+-------------+
                             |
                   Pass? ----+---- Fail?
                    |               |
                    v               v
               [DONE 100%]    +---------------------------+
                              | Retry Count == 3 Limit?  |
                              +-------------+-------------+
                                     |
                          No --------+-------- Yes
                          |                     |
                          v                     v
              [Re-analyze Stacktrace]   [TRIGGER LOOP BREAKER]
                                        - Pause Agent Execution
                                        - Re-evaluate Architecture
                                        - Escalate to Planner/User
```

**Loop-Breaker Rule:**
- If the agent performs **3 consecutive failing patches** on the same test case, agy-kit will automatically abort the turn.
- The agent is forced to stop, output a deadlock analysis report, and suggest redirection to the Architect (Planner) or user for assistance.
